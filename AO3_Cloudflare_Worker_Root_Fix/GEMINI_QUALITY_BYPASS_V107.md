# Gemini 결과 품질 검사 우회 — v107

## 변경 이유
Gemini의 HTTP 성공 응답이 영어 원문 잔존, 문장 완결성, 응답 문단 수 검사에서 거부되면 같은 번역 작업이 다음 Gemini 키를 호출했습니다. 이로 인해 정상 응답이 불필요한 추가 요청과 할당량 소모를 일으킬 수 있었습니다.

## 동작 변경
- Gemini 응답이 HTTP 성공으로 돌아오면 영어 잔존·미완성 문장 검사 함수를 호출하지 않습니다.
- Gemini 응답은 `qualityParagraphCountEnabled` 및 `qualityEnglishResidueEnabled` 설정을 읽지 않습니다.
- 문단 수가 맞지 않는다는 이유로 결과를 거부하거나 다음 Gemini 키를 호출하지 않습니다. 추가 조각은 마지막 목표 문단에 합치고, 부족한 슬롯은 빈 문자열로 매핑합니다. 챕터 저장 단계의 빈 번역 보호는 유지해 누락된 문단이 번역 완료로 저장되지 않도록 합니다.
- HTTP 오류, 네트워크 오류, 타임아웃 및 Gemini 키 냉각 처리는 기존과 같이 다음 키 시도에 영향을 줍니다. 이들은 결과 품질 검사와 별개입니다.
- 품질 검사 설정은 Cloudflare Workers AI, Groq, Azure Translator 응답에 계속 적용됩니다.
- Gemini 키 순환 커서를 같은 키 인덱스로 두 번 기록하던 중복 호출도 제거했습니다.

## 검증
- `npm run check` 통과.
- 모든 `.js`, `.cjs`, `.mjs` 파일 구문 검사 통과.
- 모의 HTTP 200 응답에 영어 원문이 있어도 품질 검사 함수 호출 0회, 다음 Gemini 키 요청 0회를 확인.
- 모의 HTTP 200 응답의 문단 수가 원문과 달라도 그 이유로 다음 Gemini 키를 호출하지 않는 것을 확인.
- HTTP 오류 시 모든 Gemini 키 두 차례 순회와 냉각 켜기/끄기 테스트 통과.

실제 Gemini API 계정과 Google Drive 계정에서의 네트워크 실험은 이 테스트에 포함되지 않습니다.
