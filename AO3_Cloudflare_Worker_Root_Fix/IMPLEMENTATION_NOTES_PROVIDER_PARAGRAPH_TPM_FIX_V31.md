# 공급자 문단 정렬·Groq TPM·취소 오류 보완 v31

## 변경 사항
- Workers AI와 Groq가 2문단 묶음 응답에서 문단 수를 틀리거나 빈 문단을 반환하면, 해당 묶음만 1문단씩 재요청해 정렬을 복구합니다. 정상 요청은 기존 2문단 배치를 유지합니다.
- 1문단 재시도 응답에 모델이 실수로 `<<<P_SEP>>>`를 내보내더라도 Worker가 비어 있지 않은 조각을 합쳐 한 문단으로 반환합니다. 여러 원문 문단의 정렬이 불분명한 응답은 여전히 거부됩니다.
- 오류 응답에 `reason`, 기대/실제 문단 수, 빈 문단 인덱스를 포함해 `expected 2 / received 2` 같은 모호한 로그를 개선했습니다.
- Groq의 `max_completion_tokens` 예약량을 입력 길이에 비례해 512~3072 범위로 조정해 짧은 번역 요청의 과도한 토큰 예약을 줄였습니다.
- Groq HTTP 429에서 공급자가 구체적인 재시도 시간을 알려준 경우(예: 6.86초) 그 시간+완충 시간을 기준으로 쿨다운하고, 시간이 없을 때는 60초를 기본값으로 유지합니다. 실패한 요청은 저장하지 않고 대체 공급자로 계속 진행합니다.
- Azure가 유효한 번역을 먼저 반환해 Groq 요청을 취소한 경우, 의도적인 취소를 오류 기록으로 남기지 않습니다. 요청 자체가 시간 초과된 경우에는 명확한 timeout 메시지를 표시합니다.

## 검증 범위
- Worker JavaScript 및 shared module 문법 검사
- HTML 4개 복사본의 인라인 스크립트 문법 검사 및 동일성 확인
- ZIP 무결성 검사
- API 응답 파서 테스트(2개 원문에 3개 출력, 빈 출력, 단일 문단에 불필요한 구분자)

라이브 Groq/Cloudflare 계정으로 실제 번역이나 사용량 한도 테스트는 수행하지 않았습니다.
