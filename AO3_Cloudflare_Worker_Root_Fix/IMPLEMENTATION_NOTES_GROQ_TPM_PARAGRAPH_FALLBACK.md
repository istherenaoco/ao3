# Groq TPM 및 문단 수 불일치 처리 개선

## 변경 사항
- Groq 번역 묶음을 3문단에서 2문단으로 줄이고 이전 문맥 전송 길이도 2,500자에서 1,500자로 줄여 출력 문단 수 불일치와 TPM 부담을 완화했습니다.
- Worker의 Groq `max_tokens`를 배치 글자 수에 비례해 1,024~4,096 사이로 설정합니다(기존 고정 8,192).
- Groq에서 문단 구분 수가 맞지 않으면 `reason: paragraph_count_mismatch`와 기대/실제 문단 수를 반환합니다. 클라이언트는 해당 번역 결과를 저장하지 않고 Azure/기존 대체 경로로 이동합니다. 문단 불일치에 대해 Groq 재시도 루프를 추가하지 않았습니다.
- 429는 서버의 `Retry-After` 또는 오류 본문에 안내된 시간으로 한 번만 재시도합니다. 재시도 후에도 429면 최소 60초, 최대 15분 쿨다운을 설정합니다.
- Groq 쿨다운 종료 시각을 `localStorage`에 보관해 새로고침 후에도 바로 다시 요청하지 않습니다.
- 번역 설정에 `Groq 자동 사용` 체크박스를 추가했습니다. 끄면 Groq에 요청하지 않고 Azure/기존 대체 경로로 진행합니다. 설정은 로컬 및 암호화 Drive 설정 백업에 저장됩니다.

## 검증
- `src/index.js` 및 `src/shared.js` Node 문법 검사
- HTML 4개 복사본의 SHA-256 일치 확인
- 인라인 JavaScript 4개 HTML 파일 모두 문법 검사
- Worker 단위 모의 응답 테스트(성공, 문단 불일치, 429 헤더 전달)
- ZIP 무결성 검사

라이브 Groq 키를 사용한 실제 번역은 테스트하지 않았습니다. 실제 할당량과 모델 출력은 Groq 계정/모델 상태에 따라 달라질 수 있습니다.
